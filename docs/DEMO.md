# RailShot AI 3分デモ手順

## デモ前チェック

```bash
npm install
npm run gtfs:import
npm run dev
```

ブラウザで `http://localhost:3000` を開く。通常のAI経路を使う場合は、`.env.local` に有効な `ORCAROUTER_API_KEY` が設定されていることを確認する。APIキーの値は画面共有、ログ、Gitに出さない。

デモはリポジトリ内の固定データを使用する。

- 地図初期位置: `src/config/map.ts`。読み込み後はデモ路線全体へ自動調整
- 通過列車検索日: `2026-08-14`
- AIプラン検索日: `2026-08-16`
- GTFS: `data/gtfs/demo/`（1路線、6駅、12列車）
- 撮影地点: `data/shooting_spots.json`（approved 3地点）

## 通常デモ経路

1. 地図中央付近のオレンジ色の線路をクリックする。
2. 「この地点を通過する列車」が表示されたら、`OUT_003`（車両：Series-A）を選ぶ。
3. 列車詳細で「選択地点」と推定通過時刻を示す。
4. 「戻る」で通過列車一覧へ戻る。
5. 右パネル上部のAI入力欄へ移動する。
6. 次の固定入力で「撮影プランを検索」を押す。

```text
2026-08-16の午後にSeries-Aを撮りたい。駅から10分以内で、できれば光線条件がいい場所
```

7. 「AIが理解した条件」と「おすすめ撮影地点」を示す。
8. 1位の「川原公園デッキ」をクリックする。
9. 地図が候補へ移動し、撮影地点マーカーと対象tripのshapeが強調されることを示す。
10. カードの通過時刻、最寄駅、徒歩時間、推薦理由を示す。

## AIが解析すべき条件

```json
{
  "vehicleSeries": "Series-A",
  "tripId": null,
  "date": "2026-08-16",
  "startTime": "12:00",
  "endTime": "17:00",
  "maxWalkMinutes": 10,
  "lightingPreference": "good"
}
```

## 想定される検索結果

- 6候補
- 1位: 川原公園デッキ / `OUT_003` / 12:30ごろ / 川原駅から徒歩6分
- 2位: 水辺プロムナード / `OUT_003` / 12:10ごろ / 水辺駅から徒歩7分
- 3位: 緑丘展望歩道 / `OUT_003` / 12:18ごろ / 緑丘駅から徒歩9分

光線スコアを含む点数は固定データから決定的に計算する。光線評価は参考指標であり、天候や現地の遮蔽物を保証しない。

## OrcaRouter障害時

AIエラーには「AI撮影プランナーに接続できませんでした」と表示される。地図、線路クリック、通過列車一覧、列車詳細はローカルSQLiteでそのまま利用できる。

AIエラー時だけ表示される「事前定義条件で検索（AI未使用）」を押すと、上記の固定条件を直接 `planner/search` へ渡せる。画面には「デモ緊急モード：OrcaRouterは使用していません」と表示されるため、通常のAI解析結果とは明確に区別される。

通常経路へ戻す場合は、OrcaRouterまたはネットワークの復旧後に再度「撮影プランを検索」を押す。
